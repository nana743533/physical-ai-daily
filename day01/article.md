## 使う道具

**Gymnasium** は、強化学習の環境（エージェントが相互作用する相手）を共通のインターフェースで提供する Python のライブラリです。`env.reset()` で環境を初期状態にし、`env.step(行動)` で1ステップ進めると、次の状態と報酬と終了の有無が返ってきます。どの環境もこの2つの関数で動かせます。公式ドキュメントは https://gymnasium.farama.org/ です。

余談ですが、Gymnasium は OpenAI が 2016 年に公開した Gym の後継で、2022 年から Farama Foundation という非営利団体が引き継いで保守しています。古い記事やコードで `import gym` と書いてあるものは、この前身を使っています。

**CartPole-v1** は Gymnasium に入っている環境の1つで、この記事で扱う倒立振子です。環境の仕様は https://gymnasium.farama.org/environments/classic_control/cart_pole/ にあります。名前の末尾の v1 はバージョンで、v0 は 200 ステップで打ち切り、v1 は 500 ステップで打ち切りという違いがあります。

余談ですが、この倒立振子の問題は Barto、Sutton、Anderson が 1983 年の論文で強化学習の例題として使ったもので、40 年以上前から同じ問題が使われています。

## 倒立振子（CartPole）とは何か

台車の上に棒が立っていて、棒が倒れないように台車を左右に動かす問題です。1ステップごとに「左に押す」か「右に押す」かを選びます。棒が鉛直から 12 度以上傾くか、台車が中央から 2.4 以上離れたらそこで終わりです。500 ステップ耐えると打ち切りで、それが満点です。

1ステップ耐えるごとに報酬が 1 もらえるので、「何ステップ耐えたか」がそのまま得点です。

## 強化学習が解く問題を、マルコフ決定過程として定義する

強化学習では、問題を**マルコフ決定過程**（Markov decision process、MDP）として定めます。MDP は次の要素の組です。

- 状態の集合 $\mathcal{S}$
- 行動の集合 $\mathcal{A}$
- 状態遷移確率 $p(s' \mid s, a)$。状態 $s$ で行動 $a$ を取ったとき、次の状態が $s'$ になる確率
- 報酬関数 $r(s, a)$。状態 $s$ で行動 $a$ を取ったときに受け取る報酬（確率変数のこともあります）
- 割引率 $\gamma \in [0, 1]$。これは次の記事で扱います

エージェントと環境のやり取りは、時刻 $t = 0, 1, 2, \ldots$ で次のように進みます。エージェントは状態 $S_t$ を観測し、行動 $A_t$ を選びます。環境は報酬 $R_{t+1}$ と次の状態 $S_{t+1} \sim p(\cdot \mid S_t, A_t)$ を返します。

行動を選ぶルールが**方策**（policy）$\pi$ で、状態 $s$ で行動 $a$ を取る確率 $\pi(a \mid s)$ として定義します。強化学習が学習で変えるのはこの $\pi$ だけで、$p$ と $r$ は環境の側にあって変えられません。

名前に付いている「マルコフ」は、次の状態と報酬の分布が、現在の状態と行動だけで決まるという性質のことです。

```math
\Pr(S_{t+1}, R_{t+1} \mid S_0, A_0, \ldots, S_t, A_t) = \Pr(S_{t+1}, R_{t+1} \mid S_t, A_t)
```

過去の履歴を全部覚えていなくても、現在の状態だけ見れば先の予測に十分だ、という仮定です。CartPole でこの仮定が成り立つように、状態には位置と角度だけでなく速度と角速度も含めてあります。位置と角度だけだと、次の瞬間にどちらへ動くかが決まらないからです。

CartPole に当てはめると次のようになります。

- $\mathcal{S} = \mathbb{R}^4$。台車の位置 $x$、台車の速度 $\dot{x}$、棒の角度 $\theta$、棒の角速度 $\dot{\theta}$ の4つの実数です
- $\mathcal{A} = \{0, 1\}$。0 が左に押す、1 が右に押すです
- $p(s' \mid s, a)$ は台車と棒の運動方程式で決まります。CartPole では乱数を使わないので、$s$ と $a$ が決まれば $s'$ は1つに決まります。終了条件（$|\theta| > 12°$ または $|x| > 2.4$）を満たすと、そこでエピソードが終わります
- $r(s, a) = 1$。どの状態でどの行動を取っても、1ステップ生き延びるごとに 1 です

この記事の方策は、状態を見ずにコイン投げで左右を決めるランダムな方策、つまり $\pi(0 \mid s) = \pi(1 \mid s) = 1/2$ です。学習を何もしていない方策の成績を先に測っておき、学習を入れた方策と比べます。

教師あり学習と違うのは、正解の行動を誰も教えてくれないことです。「この状態では右が正解」というラベルはなく、何ステップか後に「倒れた」という結果だけが返ってきます。どの行動が良かったのかを結果から逆算する必要があって、それが強化学習の難しさの中心です。

## やったこと

`CartPole-v1` を 1,000 エピソード動かしました。エピソードとは、初期化してから終了条件を満たすか打ち切られるまでの1回分のことです。各ステップの行動は `numpy` の乱数で 0 か 1 を選んでいます。

```python
import gymnasium as gym
import numpy as np

env = gym.make("CartPole-v1")      # 倒立振子の環境を用意する
rng = np.random.default_rng(0)     # 乱数の種を固定する（再現できるように）
lengths = []                       # 各エピソードで何ステップ耐えたかを入れる
for ep in range(1000):
    obs, info = env.reset(seed=ep)  # 棒をほぼ直立の状態に戻す
    steps = 0
    while True:
        action = int(rng.integers(env.action_space.n))  # 0 か 1 をコイン投げで選ぶ
        obs, reward, terminated, truncated, info = env.step(action)  # 1 ステップ進める
        steps += 1
        if terminated or truncated:  # 倒れたか、500 ステップに達したら終わり
            break
    lengths.append(steps)
```

`env.step()` が返す `terminated` と `truncated` は、どちらもエピソードが終わったことを示す真偽値ですが、意味が違います。`terminated` は MDP の終了状態に到達したこと（棒が倒れた、台車がはみ出た）で、`truncated` は MDP の外側で決めた時間切れ（500 ステップに達した）です。この区別は、次の記事で扱う収益を計算するときに「この先まだ報酬が続いたはずか」を判断するために必要になります。この実験では `truncated` は一度も立ちませんでした。

## 結果

1,000 回の平均は **22.2 ステップ**でした。

| 項目 | 値 |
|---|---|
| 平均 | 22.2 ステップ |
| 中央値 | 19 ステップ |
| 最短 | 8 ステップ |
| 最長 | 76 ステップ |
| 上位 10% の境目 | 38 ステップ |
| 100 ステップ以上耐えた回数 | 0 回 |

![倒れるまでのステップ数の分布](https://raw.githubusercontent.com/nana743533/physical-ai-daily/master/day01/hist.png)

分布は右に裾が長い形です。10〜20 ステップに半分以上が集まっていて、50 ステップを超えたのが 1,000 回のうち 50 回ほど、最長でも 76 ステップでした。ランダムな方策では 100 ステップに届きません。

8 ステップより短いエピソードが無いのは、初期状態が各成分とも $[-0.05, 0.05]$ の一様乱数で、ほぼ直立かつほぼ静止から始まるためです。そこからどう押しても、12 度傾くまでに 8 ステップかかります。

## 分かったこと

- 学習なしの CartPole は平均 22.2 ステップ、最長でも 76 ステップで倒れる。満点の 500 とは 20 倍以上の差がある
- 強化学習の問題は MDP $(\mathcal{S}, \mathcal{A}, p, r, \gamma)$ と方策 $\pi(a \mid s)$ で定める。学習で変えるのは $\pi$ だけ
- 正解の行動は教えてもらえず、倒れたという結果だけが返ってくる。結果からどの行動が良かったかを逆算するのが、この先の記事でやることの中身

次の記事は、1 エピソードぶんの報酬をどう足し合わせるかの話です。収益と割引率 $\gamma$ を定義し、$\gamma$ を 0.9 から 0.99 に変えると、この記事と同じ 1,000 エピソードの価値がどう変わるかを計算します。
