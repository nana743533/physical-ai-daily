## 今の決まり

- 1本は「1つの概念 ＋ その日に自分で動かした数字」。概念だけの記事は出さない
- 構成: はじめに → 概念 → やったこと → 結果 → 今日分かったこと → 明日の予告 → 検証環境
- 数字は実験で出たものだけ。出なかった数字は書かない。手元で確かめた範囲より先のことを言い切らない（推論で書くときは「〜のはず」「〜は4日目に確かめる」と書く）
- 社名・案件名・人名・金額は書かない
- ダッシュ（—）、ダブルクォート（“ ” と本文中の "）、「効く」は使わない。保存前に grep して 0 件にする（コードブロックの中の " は可）
- 記事の先頭に GitHub の該当フォルダ、末尾に検証環境（バージョン・OS・実行日）
- 図は `https://raw.githubusercontent.com/nana743533/physical-ai-daily/master/dayNN/...`。master に入ってから記事を出す
- タイトルは「強い言葉＋欲しい成果＋知らない概念」「〜に正解を出してみる」「網羅＋権威付け」のどれかの型。〇は実験後に数字を入れる
- 文章の書き方は readable-docs.md と reply-task-drafts.md の添削に従う（予告文を書かない、抽象語を使わない、否定を先に並べない）
- 書き方にスキルや外部の手本は使っていない（2026-10-19 時点）。手本の記事をもらったら、ここに URL と「何を真似るか」を書く
