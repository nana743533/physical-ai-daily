## 収益、割引率、価値関数の定義

前回の MDP の記法をそのまま使います。時刻 $t$ の状態を $S_t$、行動を $A_t$、その結果として受け取る報酬を $R_{t+1}$ と書きます。

### 収益

時刻 $t$ 以降に受け取る報酬を、$k$ ステップ先のものに $\gamma^k$ の重みを付けて足したものを**収益**（return）$G_t$ と定義します。

```math
G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}
```

$\gamma \in [0, 1]$ が**割引率**（discount rate）です。エピソードが時刻 $T$ で終わる場合は、$T$ 以降の報酬を 0 とみなして同じ式を使います。

この定義から、収益は1ステップ分の漸化式を満たします。

```math
G_t = R_{t+1} + \gamma G_{t+1}
```

「いまの収益は、直後の報酬と、次の時刻の収益を $\gamma$ 倍したものの和」という関係で、以降の記事に出てくるベルマン方程式はこの式が元になっています。

### なぜ割引率を入れるか

理由は2つあります。

1つ目は収束のためです。報酬の絶対値に上限 $R_{\max}$ があれば、$\gamma < 1$ のとき無限和が有限になります。

```math
|G_t| \le \sum_{k=0}^{\infty} \gamma^k R_{\max} = \frac{R_{\max}}{1 - \gamma}
```

終わりのないタスクでは、$\gamma = 1$ だと収益が発散して比べられません。$\gamma = 1$ を使えるのは、エピソードが必ず有限の時刻で終わるときだけです。

2つ目は、遠い将来の報酬を近い報酬より小さく評価するためです。遠い将来ほど予測が不確かなので、近い報酬に重みを置いた方が推定の分散が小さくなります。これは後の記事で学習の安定性を見るときに確かめます。

### 1 / (1 - γ) という目安

毎ステップ報酬 1 が永遠に続くとき、収益は等比数列の和で $1 / (1 - \gamma)$ になります。

```math
\sum_{k=0}^{\infty} \gamma^k = \frac{1}{1 - \gamma}
```

$\gamma = 0.9$ なら 10、$\gamma = 0.99$ なら 100 です。$\gamma^k$ の重みは $k \approx 1 / (1 - \gamma)$ のあたりで $1/e \approx 0.37$ まで下がるので、この値は「収益に実質的に寄与するステップ数」の目安になります。$\gamma = 0.9$ では 10 ステップ先、$\gamma = 0.99$ では 100 ステップ先より向こうの報酬は、収益にほとんど入ってきません。

### 価値関数

方策 $\pi$ に従ったとき、状態 $s$ から始めた収益の期待値を**状態価値関数**（state-value function）と定義します。

```math
V^{\pi}(s) = \mathbb{E}_{\pi}\left[ G_t \mid S_t = s \right]
```

期待値は、方策 $\pi$ による行動の選択と、状態遷移確率 $p$ の両方について取ります。1 回のエピソードの $G_t$ は確率変数の実現値で、同じ状態から何回も始めて標本平均を取れば、大数の法則によって $V^{\pi}(s)$ に近づきます。

この記事で計算する「1,000 エピソードの収益の平均」は、CartPole の初期状態 $s_0$ における、ランダム方策 $\pi_{\text{rand}}$ の価値 $V^{\pi_{\text{rand}}}(s_0)$ の推定値です（初期状態は小さな乱数で散らばるので、厳密にはその分布についての平均です）。強化学習の目的は $V^{\pi}(s_0)$ を最大にする $\pi$ を見つけることで、この先の記事で出てくる学習は、この価値を手がかりにして方策を直していく話になります。

## やったこと

CartPole は終了まで毎ステップ $R_{t+1} = 1$ なので、長さ $L$ のエピソードの $t = 0$ からの収益は等比数列の和で閉じた形になります。

```math
G_0 = \sum_{k=0}^{L-1} \gamma^k = \begin{cases} \dfrac{1 - \gamma^L}{1 - \gamma} & (\gamma < 1) \\[8pt] L & (\gamma = 1) \end{cases}
```

前回保存した 1,000 本のエピソード長から、$\gamma = 0.9, 0.99, 1.0$ の3通りで $G_0$ を計算しました。

```python
import json
import numpy as np

# 前回の実験で保存した、1,000 エピソードぶんの「倒れるまでのステップ数」を読む
lengths = np.array(json.load(open("day01/result.json"))["lengths"])

def discounted_return(length, gamma):
    """毎ステップ報酬 1 のエピソードの収益 G_0。length はステップ数（配列でもよい）"""
    length = np.asarray(length, dtype=float)
    if gamma == 1.0:
        return length                                  # 割り引かないなら収益 = ステップ数
    return (1.0 - gamma ** length) / (1.0 - gamma)     # 等比数列の和

for gamma in [0.9, 0.99, 1.0]:
    G = discounted_return(lengths, gamma)              # 1,000 本ぶんの収益
    print(gamma, G.mean(), G.max(), discounted_return(500, gamma))
```

最後の `discounted_return(500, gamma)` は、満点の 500 ステップ耐えたときの収益です。ランダム方策の平均がその何割かを見るために出しました。

## 結果

同じ 1,000 エピソードの収益の平均は、$\gamma = 0.9$ で **8.5**、$\gamma = 0.99$ で **19.5**、$\gamma = 1.0$ で **22.2** でした。0.9 から 0.99 に変えると 2.3 倍です。

| γ | 平均 | 中央値 | 最小 | 最大 | 500 ステップ耐えたときの収益 | 平均はその何割か |
|---|---|---|---|---|---|---|
| 0.9 | 8.5 | 8.6 | 5.7 | 10.0 | 10.0 | 85% |
| 0.99 | 19.5 | 17.4 | 7.7 | 53.4 | 99.3 | 20% |
| 1.0 | 22.2 | 19.0 | 8.0 | 76.0 | 500.0 | 4.4% |

![同じ 1,000 エピソードの収益を、割引率だけ変えて数え直した分布](https://raw.githubusercontent.com/nana743533/physical-ai-daily/master/day02/returns_hist.png)

分布の形が $\gamma$ で違います。$\gamma = 1.0$ では前回の分布そのままで、右に裾が長い形です。$\gamma = 0.99$ では最大が 53.4 になり、裾が短くなります。$\gamma = 0.9$ では上限の 10 を超えられないので、エピソードの多くが 9 から 10 の間に集まり、左に裾が長い形になります。

右端の列を見ると、$\gamma = 0.9$ ではランダムな方策のエピソードが満点の 85% の収益を持っています。$\gamma = 1.0$ なら 4.4% です。

![エピソードの長さと収益の関係](https://raw.githubusercontent.com/nana743533/physical-ai-daily/master/day02/return_vs_length.png)

長さ $L$ と収益 $G_0$ の関係を描くと理由が分かります。$\gamma = 0.9$ では $G_0 = 10(1 - 0.9^L)$ で、$L = 20$ で 8.8、$L = 30$ で 9.58、最長の $L = 76$ で 9.997、$L = 500$ でも 10.0 です。30 ステップと 500 ステップの収益の差が 0.42 しかありません。

$\gamma = 0.99$ では同じ 30 ステップと 76 ステップが 26.0 と 53.4 で、2 倍の差が残ります。

## 分かったこと

- 収益 $G_t = \sum_k \gamma^k R_{t+k+1}$ は $\gamma < 1$ なら必ず有限で、$1 / (1 - \gamma)$ が収益に実質的に寄与するステップ数の目安になる。0.9 は 10 ステップ、0.99 は 100 ステップ
- 同じ 1,000 エピソードでも、$\gamma$ を 0.9 から 0.99 にすると平均の収益が 8.5 から 19.5 へ 2.3 倍になる。収益の値は $\gamma$ を決めて初めて比べられる
- $\gamma = 0.9$ の CartPole では、30 ステップ耐えるのと 500 ステップ耐えるのが 9.58 と 10.0 でほぼ区別がつかない。満点の 500 まで伸ばしたいなら、500 ステップ先の差が収益に残る $\gamma = 0.99$ のような値が要る。CartPole の実装例で $\gamma = 0.99$ が多いのはこのためだと理解した。学習で本当に差が出るかは、Q 学習をやる4本目以降の記事で確かめる
- 1,000 回の収益の標本平均は、ランダム方策のもとでの初期状態の価値 $V^{\pi}(s_0)$ の推定値。方策を良くするとは、この値を上げること

次の記事は、環境のルール、つまり状態遷移確率 $p(s' \mid s, a)$ と報酬 $r(s, a)$ が全部分かっているときの話です。その場合は試行錯誤の学習をしなくても、ベルマン方程式を繰り返し解くだけで最適な方策が求まります。氷の上を滑る FrozenLake を価値反復で解いて、成功率を出します。
